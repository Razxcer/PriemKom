# 🤖 RPA-система обработки заявлений абитуриентов

Инструмент браузерной автоматизации (RPA) на базе **Playwright** для сбора данных, скачивания документов и ведения реестра поступающих в приёмной комиссии колледжа.

---

## 🎯 Проблема и решение

**Проблема:** Во время приёмной кампании (до 1000 заявлений) специалисту приходилось вручную открывать каждую анкету на закрытом образовательном портале, переписывать данные в общую таблицу и поштучно скачивать прикреплённые сканы документов. На одну заявку уходило около **5 минут** монотонного труда, а отсутствие публичного API на портале не позволяло настроить стандартную интеграцию.

**Решение:** Разработан скрипт на Playwright, который эмулирует действия пользователя в браузере, берёт на себя весь рутинный сбор информации и файловый менеджмент, оставляя человеку только финальную визуальную проверку документов и выставление статуса.

---

## 📊 Результаты внедрения (Метрики)

* **Время работы скрипта:** ~10 секунд на сбор данных и файлов по одной анкете.
* **Ручной труд специалиста:** сокращён **в 5 раз** — с 5 минут до 1 минуты на заявку (только проверка и принятие решения).
* **Масштаб:** система успешно отработала на потоке до **1000 заявлений** за время приёмной кампании (экономия более 60 часов рабочего времени).

---

## ⚙️ Алгоритм работы (Pipeline)

1. **Авторизация и навигация.** Скрипт запускает браузерный контекст, проходит аутентификацию на портале приёмной комиссии и переходит к списку необработанных заявлений.
2. **Парсинг карточки абитуриента.** Система последовательно открывает анкеты и извлекает ключевые данные (ФИО, контактную информацию, выбранную специальность, баллы аттестата и статус).
3. **Файловый менеджмент.** Под каждого поступающего автоматически создаётся изолированная локальная директория (с нормализованным именем), куда пакетно скачиваются все прикреплённые документы (паспорт, аттестат, СНИЛС, заявления).
4. **Ведение облачного реестра.** Собранные данные в реальном времени записываются новой строкой в **Google Таблицы** через официальный Google Sheets API (с проверкой на дубликаты).
5. **Финальный этап (Human-in-the-loop).** Специалист открывает уже готовую папку с документами на ПК, проверяет корректность сканов и выставляет итоговый статус заявления на портале.

---

## 🛠 Стек технологий

* **Автоматизация и парсинг:** Playwright
* **Интеграции:** Google Sheets API (авторизация через Service Account / OAuth 2.0)
* **Работа с данными и ОС:** Модули работы с файловой системой (FS), обработка путей и асинхронное скачивание потоков
* **Язык разработки:** JavaScript

---

## 🔒 Примечание по безопасности

В связи с обработкой персональных данных абитуриентов (152-ФЗ) и использованием закрытого внутреннего портала, конфигурационные файлы, ключи сервисного аккаунта Google и URL-адреса целевой системы исключены из публичного репозитория.
